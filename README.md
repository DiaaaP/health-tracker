# Sana — health tracker

Учебный трекер женского здоровья с интерфейсом на казахском и русском языках.

## Структура

```text
frontend/   HTML, CSS и JavaScript
backend/    FastAPI, Pydantic и SQLite
docs/       материалы для защиты
```

## Локальный запуск полной версии

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --reload
```

После запуска:

- приложение: http://127.0.0.1:8000/
- Swagger API: http://127.0.0.1:8000/docs
- проверка backend: http://127.0.0.1:8000/api/health

SQLite-база `backend/sana.db` создаётся автоматически и не сохраняется в Git.

## Календарь и журнал

- `GET /api/calendar?year=2026&month=10` — возвращает рассчитанный календарь.
- `GET /api/logs` и `POST /api/logs` — читают и сохраняют дневную запись; повторное
  сохранение той же даты обновляет запись, а не создаёт дубль.
- `GET /api/periods` и `POST /api/periods` — читают и отмечают менструацию.
- `DELETE /api/periods/{id}` — удаляет ошибочную отметку.

Прогноз появляется только после первой отметки менструации. Если сохранено два
или больше начала цикла, средняя длина рассчитывается по реальным интервалам.
При недостатке данных используется базовый цикл 28 дней и длительность 5 дней;
интерфейс явно помечает будущие даты как прогноз, а не как медицинский факт.

## Регистрация

- `POST /api/auth/register` — создаёт пользователя.
- `POST /api/auth/login` — проверяет email и пароль.

Пользователи сохраняются в таблице `users`. Пароли в открытом виде не хранятся:
backend сохраняет только защищённый hash с индивидуальной солью. Проверить оба
запроса можно через Swagger по адресу http://127.0.0.1:8000/docs.

## Локальный AI-чат через Ollama

AI-чат работает напрямую из браузера с локальной Ollama. Backend проекта для
этого менять не нужно.

### 1. Установка на Windows

Скачайте Ollama с https://ollama.com/download/windows или установите через
PowerShell:

```powershell
irm https://ollama.com/install.ps1 | iex
```

Закройте и заново откройте PowerShell, затем загрузите модель:

```powershell
ollama pull qwen2.5:3b
ollama list
```

Если у вас уже загружена другая модель, скачивать эту необязательно: впишите её
точное имя из `ollama list` в поле «Модель Ollama» на странице AI-чата.

При запуске `backend/main.py` приложение само проверяет порт `11434`. Если
Ollama выключена, Sana запускает `ollama serve` в фоне и останавливает этот
процесс вместе с FastAPI. Если Ollama уже была запущена отдельно, Sana использует
её, но не завершает при остановке — приложение не закрывает чужие процессы.

### 2. Проверка локального подключения

Откройте http://127.0.0.1:11434/api/tags. Если браузер показывает JSON со
списком моделей, Ollama работает. Затем откройте раздел `AI-чат` в Sana и
укажите в поле точное имя установленной модели, например `qwen2.5:3b`.

Локальная страница `http://127.0.0.1:8000` подключается без дополнительной
настройки. Чтобы AI-чат работал и на GitHub Pages с этого же компьютера, добавьте
пользовательскую переменную среды Windows:

```text
Имя: OLLAMA_ORIGINS
Значение: https://diaaap.github.io,http://127.0.0.1:8000,http://localhost:8000
```

Для этого полностью закройте Ollama через значок в системном трее, откройте
«Изменение переменных среды текущего пользователя», создайте переменную и снова
запустите Ollama из меню «Пуск». В адресе GitHub Pages путь `/health-tracker/`
указывать не нужно: origin состоит только из протокола и домена.

Адрес Ollama во frontend уже настроен: `http://127.0.0.1:11434`. Публичная
страница может обращаться только к Ollama на том компьютере, где она открыта.
Ответы AI используются только как общая информация и не заменяют врача.
