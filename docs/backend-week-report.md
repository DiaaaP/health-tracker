# Backend: объём работы на одну неделю

Это реалистичный отчёт для учебного спринта. Он описывает готовый результат,
а не утверждает, сколько времени фактически заняло написание кода.

## День 1 — база данных

- Добавлена таблица `sessions`.
- В `daily_logs` и `periods` добавлено поле `user_id`.
- Сделана безопасная миграция уже существующей SQLite-базы: таблицы и столбцы
  создаются только тогда, когда их ещё нет.
- Добавлены индексы для поиска сессии и пользовательских записей.

## День 2 — регистрация и вход

- Пароль хранится только в виде PBKDF2 hash с отдельной солью.
- После регистрации и входа сервер выдаёт случайный Bearer-токен.
- В базе хранится только SHA-256 hash токена.
- Добавлены `GET /api/auth/me` и `POST /api/auth/logout`.
- Сессия автоматически истекает через 30 дней.

## День 3 — личные данные

- Записи дневника и периоды разделены по пользователям.
- Один аккаунт не может прочитать, изменить или удалить данные другого.
- Для демонстрации оставлен отдельный гостевой режим без регистрации.
- Повторное сохранение дневника за одну дату обновляет существующую запись.

## День 4 — календарь и аналитика

- Календарь строится по периодам текущего пользователя.
- Добавлено изменение даты окончания периода через `PATCH`.
- `/api/summary` считает количество записей, настроение, энергию, симптомы,
  среднюю длину цикла и среднюю длительность менструации.
- Добавлена очистка данных текущего профиля.

## День 5 — проверка и документация

- Написаны API-тесты на регистрацию, вход, выход, изоляцию пользователей,
  обновление дневника, аналитику, периоды и прогноз календаря.
- Тесты работают с временной базой и не портят пользовательские данные.
- Обновлены README и Swagger-документация.

## Короткий текст для защиты

«За неделю мы довели backend от общей демонстрационной базы до системы с
пользовательскими аккаунтами. FastAPI принимает и проверяет данные через
Pydantic, SQLite хранит пользователей, сессии, дневник и периоды. Пароли и
токены не лежат в базе открытым текстом. После входа frontend передаёт
Bearer-токен, поэтому каждый пользователь получает только свои записи.
Календарь рассчитывает прогноз по сохранённым периодам, а endpoint summary
формирует статистику настроения, энергии и симптомов. Основные сценарии
проверяются автоматическими тестами на временной базе».

## Что можно оставить на следующую лабораторную

- восстановление пароля;
- подтверждение email;
- refresh-токены;
- публикация FastAPI на отдельном сервере;
- более сложная медицинская аналитика после консультации со специалистом.
