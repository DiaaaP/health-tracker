# Текст для защиты проекта Sana

## Короткое вступление — участник 1

Здравствуйте. Наш проект называется **Sana**. Это учебное веб-приложение для
отслеживания менструального цикла, самочувствия и ежедневных симптомов.

Проблема, которую мы рассматриваем, заключается в том, что многие популярные
приложения имеют перегруженный интерфейс и не всегда адаптированы для пользователей
из Казахстана. Поэтому нашей целью было создать понятный двуязычный интерфейс на
казахском и русском языках, в котором основное действие выполняется за несколько
шагов.

Целевая аудитория проекта — девушки и женщины, которым нужен простой личный
дневник для наблюдения за циклом и общим самочувствием. Приложение не ставит
медицинский диагноз и используется только для ведения записей.

## Design / UI/UX — участник 1

В рамках UI/UX-части мы проанализировали приложения Flo, Clue, SuperMoms Club и
MamCare. Из анализа мы взяли три основных принципа: текущий статус должен быть
виден сразу, количество основных действий должно быть небольшим, а текст должен
быть коротким и легко читаемым.

В интерфейсе используется спокойная фиолетовая палитра, крупные карточки и нижняя
навигация на мобильных устройствах. Главный экран показывает день цикла, прогноз
и кнопку для внесения данных. Календарь отображает отмеченные дни и предполагаемое
фертильное окно. Отдельная форма позволяет выбрать настроение, симптомы и уровень
энергии.

Проект пока не считается полностью отполированным. Следующий этап дизайна —
унифицировать кнопки и поля формы, улучшить интервалы между элементами и собрать
в Figma простой prototype из четырёх основных экранов.

## Frontend — участник 2

Frontend реализован без фреймворков на HTML, CSS и JavaScript. Приложение состоит
из главного экрана, календаря, аналитики, профиля и формы ежедневной записи.

JavaScript отвечает за переключение разделов, выбор языка, генерацию календаря,
выбор симптомов и отправку данных в API. Если приложение открывается через
GitHub Pages и backend недоступен, данные сохраняются в localStorage. Благодаря
этому демонстрационная версия продолжает работать отдельно от сервера.

CSS содержит desktop, tablet и mobile layouts. Интерфейс адаптируется под ширину
экрана, а на мобильных устройствах используется нижняя навигация.

Для дальнейшей работы frontend-участнику остаётся подключить endpoint аналитики,
добавить более подробные сообщения об ошибках и улучшить отображение календаря
на очень узких экранах.

## Backend — участник 3

Backend построен на FastAPI. При запуске сервер создаёт SQLite-базу и две таблицы:
ежедневные записи и даты менструации.

API содержит проверочный endpoint `/api/health`, endpoints для получения и
создания дневных записей, endpoints для дат менструации и базовый endpoint
`/api/summary`. Формат входных данных описан Pydantic-моделями. Это позволяет
FastAPI автоматически проверять типы данных и формировать Swagger-документацию.

SQLite выбран для учебного проекта, потому что он не требует отдельного сервера
базы данных и позволяет хранить информацию в одном локальном файле.

Backend остаётся намеренно небольшим. Следующими задачами являются обновление
существующей записи, более строгая проверка дат и расчёт реальной статистики цикла.

## Демонстрация

1. Открываем главный экран и показываем текущий статус цикла.
2. Переходим в календарь и выбираем день.
3. Открываем ежедневный журнал.
4. Выбираем настроение, симптомы и уровень энергии.
5. Нажимаем кнопку сохранения.
6. Показываем запрос в Swagger или список через `GET /api/logs`.
7. Переключаем язык интерфейса с казахского на русский.

## Заключение

В результате мы получили рабочую базовую full-stack версию проекта. Основной
пользовательский сценарий уже работает: пользователь может открыть приложение,
внести дневную запись и сохранить её в SQLite через FastAPI.

Проект разделён на frontend и backend, поэтому каждый участник команды может
работать в своей области независимо. При этом мы намеренно оставили несколько
небольших задач для следующей лабораторной работы: улучшение Figma-прототипа,
frontend-валидацию и расширение backend-аналитики.

## Возможные вопросы преподавателя

### Почему выбран FastAPI?

FastAPI быстро создаёт REST API, автоматически проверяет Pydantic-модели и
предоставляет Swagger-документацию без дополнительной настройки.

### Почему SQLite?

Для учебного прототипа SQLite проще отдельного сервера базы данных. При этом мы
используем обычные SQL-запросы, поэтому структуру можно позже перенести в другую СУБД.

### Где хранятся данные?

При локальном запуске записи сохраняются в `backend/sana.db`. В статической версии
GitHub Pages используется localStorage, потому что GitHub Pages не запускает Python.

### Что ещё не готово?

Не подключена динамическая аналитика, нет редактирования записей и требуется
доработка некоторых мобильных состояний. Эти задачи распределены между тремя
участниками команды.

### Как обеспечена приватность?

Проект не отправляет данные сторонним сервисам. Локальная версия хранит их в
SQLite на компьютере пользователя, а статическая версия — в localStorage браузера.
